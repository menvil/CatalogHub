## Implemented expand contract

`2026_10_05_000001_expand_global_attribute_ownership.php` adds the assignment table, identity lock, definition/option crosswalks, globally unique nullable `canonical_code`, relational measurement pair, additive Import membership FKs, and draft identity version. `2026_10_05_000002_expand_translation_locale_identity.php` adds owner/Locale-ID unique keys only to collision-free Category/Attribute/Section/Unit tables and persists which keys were installed. It never drops the locale-code unique keys or modifies a translated row. Options already have Locale-ID uniqueness. Duplicate tables retain every row and block cutover in diagnostics; a reviewed follow-up can install the deferred key after resolving collisions. Product's mixed identity is also diagnosed; Content translations have no Locale ID and are outside this Attribute owner reconciliation.

`CategoryAttributeAssignment`: bigint ID; required `central_category_id`, `attribute_definition_id`; nullable `attribute_section_id`; position; required/visible/searchable/sortable booleans; timestamps. Unique `(central_category_id, attribute_definition_id)`; supporting unique `(id, central_category_id)` and `(id, central_category_id, attribute_definition_id)`; composite Section/Category FK to the existing Section supporting key. Category/definition/Section deletion is RESTRICT. No new deletion workflow exists. Null Section means Ungrouped. It has no filterable/comparable flag. All three engines enforce the same FK membership and measurement shape; SQLite uses equivalent INSERT/UPDATE abort triggers where ALTER ADD CHECK is unavailable, PostgreSQL/MariaDB use CHECK constraints.

### Durable identity and backfill

Definition crosswalk rows retain legacy ID/Category/code, nullable selected canonical ID/code, identity status, measurement status/reason and identity version 1. Legacy columns are immutable inventory. Option crosswalks retain option ID, legacy definition ID, exact legacy code, canonical option ID/code and status. No options are merged. Ordinary option codes are immutable and hard deletion is blocked; callers may hide options with `is_visible=false`. Historical option codes remain reserved even after a previously permitted rename or deletion. A preserved crosswalk without a live canonical option is a cutover blocker; explicit audited retirement belongs to CA-022 / Phase 19.10. No Product JSON, text or values are stored in either crosswalk.

Backfill inserts one assignment for every legacy definition, preserving Section (including null), position and the four local booleans exactly. It preserves existing rows on repeat, reports drift rather than silently rewriting target decisions, and only backfills null mapping pointers. It maps exact dimension/unit catalog codes with compatible membership and numeric type; no alias/label/case guessing. Unrelated canonical edits preserve unresolved legacy measurement strings. Diagnostic legacy inventory counts include durable crosswalk identities after safe membership removal. Definition, option, value, mapping, draft, translation, display, facet and content IDs persist.

Rollback is supported before target-owner writes. A transactional write epoch records successful new-owner mutations; no-ops and rejected operations do not change it. `down` checks that epoch, new global rows, cross-Category reuse, local compatibility drift and relational mapping drift before dropping additive state. Once target writes exist it rejects automatic downgrade; backup/replay and an inverse reviewed crosswalk are required. A migration test compares all old rows/columns before expand and after safe down.

### Mutations, revisions, concurrency and audit

Backend actions: `CreateGlobalAttributeDefinitionAction`, `UpdateGlobalAttributeDefinitionAction`, `AssignAttributeToCategoryAction`, `UpdateCategoryAttributeAssignmentAction`, `MoveCategoryAttributeAssignmentAction`, `UnassignAttributeFromCategoryAction`. Assignment operations require expected Category schema revision. Move atomically compacts old/new local groups; configure accepts only the four local booleans. Target mutations use transactions and bounded retries, suppress no-op saves/events/revision changes and reject archived schemas.

Lock order for schema work is identity/membership scope → ascending Category IDs → definition/assignment rows. SQLite begins with a write to the preseeded scope; PostgreSQL/MariaDB hold its row lock. This serializes membership discovery and global-code races, with deliberately coarse schema throughput. Schema review/approval/archive/restore use the same scope. Category-only identity/lifecycle actions retain their original Category locks and are not accidentally serialized by an Attribute mutex. Global edits discover every assigned Category under that scope, lock in ID order, reject any affected archived schema, and invalidate each exactly once through Phase 19.1 `SchemaRevision::invalidate`; Reviewed/Approved become Draft and all attribution clears. Existing legacy global-definition/option paths also fan out via the centralized runner/fingerprint. No new revision mechanism exists.

Dangerous ordinary canonical code/type/dimension/unit changes reject with **explicit migration required** when Product values, mappings (including reviewed/in-flight), normalized draft ID/code references, options, translations, display rules, facets, content or multiple assignments depend on the definition. Source-name edits remain available and fan out. Unassign checks Category Product facts/mappings/drafts/facets, conservative display/content dependencies and the existing comparable flag; hide remains possible. Future comparison rows and SEO variable bindings must extend `AttributeDependencies::forDefinition` when those owners exist; no speculative owners are created here. No code/value conversion or automatic renaming path is provided.

New events: `catalog.attribute.created`, `catalog.attribute.updated`, `catalog.category.attribute.assigned`, `.configured`, `.moved`, `.unassigned`. They use the existing recorder with bounded scalar ID/code/reference/type/unit/changed-field/count allowlists and bounded per-Category `catalog.category.schema.invalidated` events. They never serialize Product facts, draft JSON, translated bodies or arbitrary config. Audit failure rolls back mutation, epoch and every revision. No retirement/option mutation path is newly introduced or claimed.

Every new backend mutation requires active actor, Central panel/page admission, `catalog.schema.manage` and `central.mutation.execute`. Category permission does not substitute. Diagnostic reads require schema permission/admission but not mutation. Role grants remain unchanged.

### Operator diagnostics and payload interpretation

Run `php artisan catalog:diagnose-attribute-globalization --actor=<active Central schema operator ID>`. Output is deterministic JSON `report_version=1`, `identity_version=1`; exit 0 means no detected cutover blocker, exit 1 means reconciliation is required. It reports legacy counts, assignment coverage/drift/checksum, duplicate codes, apparent equivalence versus incompatible groups, different-code/name-only candidates, actual selected-crosswalk Product merge collisions, Product membership/count/checksum, option vocabulary conflicts, measurement failures, Locale collisions, mapping membership, draft reference summaries/checksums, display-rule conflicts, facet/content dependencies and unresolved canonical rows. A candidate is never approved equivalence. The command performs no repairs/audit/identity initialization and exports no Product/draft/translation bodies. Totals/counts are fixture or operator-database observations, never invented production counts.

Drafts gain `attribute_identity_version=1` without JSON changes. Publish explicitly accepts only version 1; future converted versions cannot be consumed as legacy. Jobs reload stable batch/raw/draft IDs. Scalar enum values carry option codes; enum normalization metadata can additionally carry option ID/label; multi-enum carries arrays of codes. Unit codes and Category IDs remain legacy vocabulary. Retained exports/projections/snapshots are immutable and require the durable crosswalk at future conversion; none is rewritten in 19.2.

### Exact 19.3 removal/cutover backlog

Only after consumer proof, 19.3 may remove Definition `central_category_id`, `attribute_section_id`, `position`, `is_required`, `is_visible`, `is_searchable`, `is_sortable`, `is_filterable`, `is_comparable`, `dimension`, and `canonical_unit`; their legacy FKs/indexes (`attr_def_section_cat_fk`, local Category/code uniqueness, `attribute_definitions_id_category_unique` and Category/Section/flag indexes) remain until all incoming membership constraints and readers converge. Replace `attribute_mappings_definition_category_fk` and the transitional independent definition pointer only after assignment-derived meaning is authoritative. Preserve IDs/options/value snapshots and the durable crosswalks. Resolve every canonical slot explicitly before enforcing final `code` global uniqueness; the temporary `canonical_code` slot can then be contracted only after versioned payload/identity conversion. Locale-code uniqueness can be replaced only after every owner/Locale collision and reader is reconciled. The legacy validator/preview/clone/export, Product/Import, projection/search, facet and public comparison readers have deliberately not switched in 19.2. Global assignment schema validation/consumer freshness also remains that convergence gate.

Compatibility safety rejects every ordinary option code rename and hard deletion, including unreferenced options. Label, position and visibility edits remain available and preserve identity, crosswalks and Product facts. These are guards on existing paths, not a new global option authoring API or CA-022 implementation. A later legacy clone turns any provisional singleton code slot into a reported unresolved group, never an approved retained winner.

Existing Product Specs save and normalized-draft publish transactions also take the identity lock before validation/row locks. Their legacy membership/type/value storage rules remain unchanged; this prevents a canonical mutation or unassign from racing the two current Product-fact write paths without performing a consumer authority cutover.

The existing Content reference chooser uses one compatibility label formatter: legacy Category labels stay identical, while a global definition with no Category displays its source name/code safely. Its centralized compatibility query preserves existing legacy reference admission and requires active Central admission plus schema permission to list new global definitions. It does not change content relation identities or expose a schema editor. Canonical changes through the temporary legacy definition editor also emit the same bounded global update event, in addition to revision fan-out; no-op and rollback contracts apply to this bridge as well.

Review hardening keeps the expand boundary: legacy code renames share the durable reservation guard; new assignment writes require a resolved canonical code. Diagnostics key local assignments/crosswalks directly, batch duplicate-group evidence with unchanged hash inputs, and report missing Product relations as blockers. Dependency scans inspect only pending-review/approved drafts through their array cast and preload assignment Categories once. Typed translation saves lock/reload their owner and Locale and check/save transactionally, including when a collided owner table has no additive Locale-ID unique key; deferred keys still require explicit reconciliation. The historical migration owns its frozen backfill/measurement logic, batches inventory rows and caches exact measurement lookups, and never resolves live application services in either direction.

Identity integrity uses one reservation service under the existing mutex: global creates and all code renames reserve live and durable codes; legacy creates retain diagnosable live local duplicate groups but reject historical-only reservations and global ownership. Dangerous edits on an unresolved durable definition crosswalk require explicit reconciliation; source-name edits remain available. Assignment and legacy-anchor removal require both a canonical slot and a real selected crosswalk target when a crosswalk exists. Diagnostics report unresolved durable targets regardless of the compatibility Category anchor, and `option_identity_problems` blocks cutover for missing canonical options, unsupported statuses or mismatched canonical codes. No implicit promotion, option retirement or consumer authority cutover is introduced.

Existing definition unique `(id, central_category_id)` supports the Import composite FK; existing Section unique `(id, central_category_id)` supports both Section-parent and definition-placement FKs. Neither can be removed prematurely. Existing Product/definition uniqueness is also a merge constraint, not evidence that data is clean.

Deletion consequences: `central_products.central_category_id` is nullable with `nullOnDelete()`, so Products do not block Category deletion; they can lose taxonomy membership. Existing `site_categories.central_category_id` remains a separate RESTRICT guard when Site selections exist. Other Category-owned rows can cascade away. Section-parent membership uses CASCADE, while definition-to-Section membership uses RESTRICT: an assigned definition can block a Section delete, but an otherwise deletable parent can cascade through its descendant Sections and translations. Do not assume either a universal delete prohibition or an unconditional cascade. The archive-first Category decision and in-place Section flattening are application/domain requirements; they must not rely on the two incorrectly reported RESTRICT guards. No FK or runtime delete behavior is changed by this correction.

## Phase 19.1 additive implementation

`2026_10_04_200000_add_category_foundation_revisions.php` adds `category_hierarchy_scopes` with a non-null string primary key and revision, root + existing-parent scope rows at 0, and seven Category schema revision/attribution fields. Schema revision starts at 1; legacy Reviewed/Approved bind their respective metadata to 1 without actor/time invention. Names, slugs, parentage, positions, status, Products, Site selections and schema rows are unchanged. The scope table adds no FK to the four inventory targets; the 23 incoming FK declarations/ON DELETE methods above remain unchanged. Two new nullable attribution FKs point to `users` with SET NULL. Down removes only these additive structures. The migration is tested against invalid historical Category shapes and through down/up on all database engines.

Hierarchy diagnosis/explicit complete-set reorder replace migration-time normalization. Clone preserves nested/sectionless Sections until a separately reviewed future flattening plan; the existing parent CASCADE is not used as a repair tool. Current local schema actions invalidate approval transactionally; independent FacetDefinition/display-rule invalidation and projection freshness convergence remain future work. Category archive now provides workflow protection where historical SET NULL/CASCADE constraints do not.

## Safe migration sequence (future MRs)

1. **19.1 Category safety — implemented.** Inventory cycles, orphan/self parents, duplicate/gapped sibling positions and current lifecycle/schema states. Explicitly protect Product membership in actions: its current Category FK is SET NULL, not a delete guard. Future legacy Section flattening must update parent/order in place; deleting a Section parent can cascade through descendants/translations, subject to the separate definition-to-Section RESTRICT constraint. Repair only through a reviewed deterministic plan. Add hierarchy/schema revisions and explicit Category/schema actions, split permissions and audit boundaries. Remove ordinary hard-delete and direct approval dropdown writes. Keep all IDs and Site selections.
2. **19.2 Expand.** Add assignments, membership keys, relational measurements and a durable legacy-definition/option/code crosswalk. Backfill one assignment per old definition, including sectionless rows, preserving all category-local flags except authority delegated in step 4. Keep old columns/FKs usable while readers are being switched. Backfill translation locale IDs and review duplicates before unique keys.
3. **19.2 Reconcile canonical meaning.** Inventory each definition's category, code, type, dimension/unit, option vocabulary/labels, Products, mappings, translations, display rules, content relations and drafts. Group only explicitly equivalent meanings; choose a retained canonical ID. Equal codes with incompatible meaning get reviewed distinct globally unique codes; preserve old codes in the crosswalk, not category-qualified duplicate meanings. Equal meaning with conflicting copy/rules is blocked until resolved. Global uniqueness becomes mandatory before the UI can create definitions.
4. **19.2–19.3 Repoint without cascades.** Map values, options, translations, display rules, content IDs and draft references transactionally/batched with verification. Never delete old definitions before every child and non-FK reference is reconciled. Preserve raw/typed/min/max/unit/confidence/provenance fields exactly. Products with multiple old values merging into the same canonical definition require explicit conflict resolution, never last-write-wins. Equivalent enum code differences need a reviewed code map for scalar and multi-enum payloads and facet choices. Ambiguous code meaning blocks migration.
5. **19.3 Authority cutover.** Add facet assignment membership and minimal comparison rows; reconcile old flags against existing facet config and comparison behavior. Converge Product Specs, Imports/publish, facets, comparison, projection/search and export contracts as one serial prerequisite. No mutable dual-write authority; compatibility readers can read the crosswalk, but all new writes use the new owner after cutover. Replace `attribute_mappings_definition_category_fk` with assignment/category membership before removing definition category. Upgrade tests/factories to create valid shared definitions and category assignments.
6. **19.3 Derived rebuild and contraction.** Version projection/export contracts; rebuild affected Category/Product/Search Site+Locale outputs with checksum/freshness validation. Keep old snapshots immutable. Only after losslessness and old-reader removal are proved, drop obsolete local definition columns/indexes/FKs and authoritative `is_filterable`/`is_comparable`. Legacy definitions are retained until all references/rollback evidence are accounted for; deletion is not a cleanup shortcut.
7. **19.12–19.15 Owned extensions.** Localized facet override, complete comparison presentation, restricted SEO template engine/storage, and shared translation workspace workflow have explicit schema changes in their owning MRs. The comparison base and consumer authority already exist from 19.3; later UI does not reintroduce old flags. Each new entity participates in revision/freshness/audit from its first write.

Pause import publish/spec/schema writes at the migration cutover (or supply an equivalent proven lock protocol); in-flight jobs carry a payload version and cannot publish old IDs unchecked. Take a restorable backup and retain an immutable crosswalk/report. Validate row counts, typed-value/provenance checksums, mapping scope/status, translations/approval attribution, option references and constraint integrity before/after each batch. Roll back expand stages by removing unused additive structures. After remapped writes begin, downgrade requires inverse crosswalk and restored backup/replay; it is not safe to pretend a destructive down migration restores category-local meaning. No production execution is authorized by this planning MR.

## Phase 19.2 expand implementation

The [19.2 contract](../architecture/attribute-globalization-foundation.md) records the pre-migration re-audit and exact authority/compatibility table. Two additive migrations introduce CategoryAttributeAssignment, durable definition/option crosswalks, transitional unique canonical code slots, relational measurement pairs, Import assignment membership while retaining the original composite FK, draft identity version 1, and collision-guarded additive Locale-ID keys. Backfill never merges/renames/recalculates or rewrites payloads; diagnostics blocks ambiguous identity, measurements, translations and membership. New backend actions use Phase 19.1 revision/audit and deterministic global fan-out. Every old ownership column, local unique/supporting key and consumer FK remains for 19.3. The populated migration test proves exact old-field preservation and safe expand rollback before target writes. No CA screen or consumer convergence is delivered.
